# Проверка маршрутных листов (CV Pipeline)

Автономный локальный конвейер компьютерного зрения (100% On-Premise) для автоматизированной верификации сканов бумажных маршрутных листов (МЛ) в формате PDF. Система выделяет страницы с маршрутными листами и окна аптек, проверяет наличие печати, подписи и расшифровки, сверяет рукописное и печатное количество грузовых мест, контролирует секцию возврата «Получение» и формирует отчёты с визуализацией ошибок.

## Структура репозитория

- `pipeline.py` — основной модуль обработки PDF: рендеринг страниц, детекция реквизитов (`YOLOv8m`), классификация цифр (`YOLO11s-cls`), OCR служебных полей (`EasyOCR`), пространственная привязка (`SpatialResolver`), проверка бизнес-правил и формирование отчётов.
- `run_pipeline.py` — скрипт пакетного запуска проверки всех PDF из `Test_PDFs/` с сохранением результатов в `Результаты/`.
- `update.py` — скрипт обновления проекта из ветки `main` на GitHub без использования `git.exe` (для корпоративных рабочих станций).
- `requirements.txt` — список зависимостей Python.
- `Новые веса/` — верифицированные веса обученных моделей (`weights_version: waybills-cv-v1.4.1`):
  - `best_clean.pt` — детектор элементов маршрутного листа (14 классов, SHA-256: `0bdfcbbabf8a987a6f5a2cd2648f96213c65dd8225101f7b1021074ae17d2747`);
  - `best_digit_classifier.pt` — классификатор кропов печатных и рукописных цифр (39 классов, SHA-256: `48196c721a78735ee05875d9c944e128c7fc503a5f6dc9c0173368d334c40f2a`).
- `Test_PDFs/` — входной каталог для проверяемых PDF-файлов.
- `Результаты/` — выходной каталог отчётов (создаётся при запуске, не отслеживается в Git).

## Установка зависимостей

- Для CPU-сервиса (`review_service.py` в режиме `INFERENCE_MODE=http`, Kubernetes):
  ```bash
  pip install -r requirements-cpu.txt
  ```
- Для GPU-сервера инференса (`inference_server.py` на LitServe) или локального инференса (`INFERENCE_MODE=local`):
  ```bash
  pip install -r requirements-gpu.txt
  ```

Подробная инструкция по развёртыванию CPU (Docker/k8s) ↔ LiteLLM ↔ GPU (Mac LitServe) приведена в [DEPLOYMENT.md](DEPLOYMENT.md).

## Запуск

### Пакетный запуск на `Test_PDFs/`

Поместите проверяемые PDF-файлы в папку `Test_PDFs/` и выполните:

```bash
python run_pipeline.py
```

Скрипт очищает предыдущие каталоги `Результаты/Ошибки`, `Результаты/Архив` и файл `Результаты/report.txt`, затем последовательно обрабатывает все `.pdf` из `Test_PDFs/`.

### Запуск `pipeline.py` через CLI

```bash
python pipeline.py <input_dir_or_pdf> \
  --out Результаты \
  --model "Новые веса/best_clean.pt" \
  --digit_model "Новые веса/best_digit_classifier.pt"
```

Основные параметры:
- `--out` — каталог для сохранения отчётов и визуализаций (по умолчанию `Результаты`);
- `--model` — путь к весам детектора (по умолчанию `Новые веса/best_clean.pt`);
- `--digit_model` — путь к весам классификатора цифр (по умолчанию `Новые веса/best_digit_classifier.pt`);
- `--max-pages` — ограничение числа обрабатываемых страниц на один PDF (по умолчанию `150`);
- `--allow-untrusted-weights` — явное разрешение загрузки сторонних весов вне реестра SHA-256 (для экспериментов).

## Обновление без Git (`python update.py`)

Если на корпоративном компьютере запуск `git.exe` заблокирован политиками безопасности, обновить код и веса из ветки `main` можно командой:

```bash
python update.py
```

Скрипт загружает архив репозитория по HTTPS, проверяет размер архива и распаковываемых данных, защищён от Zip Slip и символических ссылок, атомарно обновляет файлы проекта и не затрагивает локальные каталоги `Результаты/`, `Старые веса/`, виртуальные окружения, `.env` и PDF-файлы в `Test_PDFs/`.

## Основные этапы работы и встроенная ИБ

1. **Контроль целостности моделей**: до загрузки весов в PyTorch вычисляется SHA-256 контрольная сумма (`_verify_weight_integrity`) и сверяется с эталонным реестром `KNOWN_HASHES` для защиты от подмены файлов и атак типа Pickle RCE.
2. **Изолированный рендеринг PDF**: страницы конвертируются в `200 DPI` (при габаритах `> 2500 pt` — fallback на `72 DPI`, лимит `150` страниц) с нормализацией в оттенки серого внутри системной временной директории (`tempfile.TemporaryDirectory`), гарантированно удаляемой после обработки.
3. **Детекция, пост-фильтрация и сегментация по МЛ**: инференс `YOLOv8m` (`imgsz=1024`, `conf=0.12`, `iou=0.45`) с классовыми порогами (`Печать`: `0.40` и проверкой плотности чернил `< 240` не менее `8.5%` при `conf < 0.85`; `Подпись`: `0.13`; `Расшифровка печать`: `0.12`; `Окно аптеки` и `Qr code`: `0.25`; остальные: `0.20`), Cross-Class NMS (`IoU > 0.75`), слиянием двузначных цифр и порогом одиночной рукописной цифры `0.30`. Пакетные PDF автоматически разделяются на отдельные МЛ по титульным страницам со сбросом нумерации страниц.
4. **Классификация цифр и пространственная привязка**: цифры вырезаются квадратным кропом (`1.4 * max_side`) и классифицируются `YOLO11s-cls` (порог уверенности `0.58`), после чего трёхуровневый `SpatialResolver` (зоны Вороного, венгерский алгоритм и арифметический оптимизатор с ограничением от перебора при `> 6` пограничных цифр) распределяет элементы по окнам аптек и проверяет регламент приёмки (включая секцию «Получение»).
5. **Выгрузка результатов**:
   - `Результаты/report.txt` — сводный реестр выявленных нарушений;
   - `Результаты/Архив/` — многостраничные PDF с разметкой окон и баннерами ошибок;
   - `Результаты/Ошибки/` — PNG-изображения проблемных страниц, сгруппированные по номеру МЛ и ФИО водителя.
